Here is a summary of the **RFObserver** (or **RFObs**) application based on the provided documentation:

### **Overview**
**RFObserver** is a Python-based software application designed to monitor, visualize, and process Radio Frequency (RF) spectra. It is specifically developed for the **Hat Creek Radio Observatory** to manage Radio Frequency Interference (RFI).
*   **Primary Goal:** Enable dynamic spectrum usage by detecting RFI in real-time, allowing the observatory to use frequencies only when the environment is clear (e.g., when the observatory is not actively observing).
*   **Hardware:** Currently tested with the **B205mini SDR** and **NVIDIA Jetson Nano** compute module.
*   **Architecture:** Built on **FastAPI** and **HTMX** for the web interface, using **SQLite** (with WAL) for local storage and **NATS JetStream** for outbound messaging.

### **Key Features & Capabilities**
*   **Real-time Monitoring:** Provides live spectral density plots (PSD), statistics (mean, std, kurtosis), and burst detection via a rolling hysteresis algorithm.
*   **Signal Processing:**
    *   Supports FM demodulation (pluggable add-ons).
    *   Generates SigMF metadata compatible with tools like Inspectrum and GNU Radio.
    *   Supports frequency sweeping.
*   **Capture Management:**
    *   **Automatic:** Continuous full-duty-cycle IQ capture triggered by power thresholds or manual request.
    *   **Manual:** On-demand capture with pre-trigger circular buffering.
    *   **Storage Formats:** Exports raw IQ data (`.sc16`), metadata (`.json`), and SigMF files.
*   **Storage Management & Safety:**
    *   Implements a "free space floor" system to prevent disk overflow.
    *   **Auto-pruning:** Automatically deletes old automatic captures (`auto/`) or prunes history (PSD/Detections) based on disk usage thresholds.
    *   **Health Monitoring:** Tracks disk health and database reusability; reports status via an API (`/api/health`).
    *   **Warning System:** Flags "degraded" status if manual captures are deleted or write failures occur, persisting this warning until resolved.
*   **Integration:**
    *   Pushes data to **OpenZMS** (via SigMF) and **NATS JetStream**.
    *   Includes a mock receiver for development and testing without hardware.

### **System Architecture & Workflow**
1.  **Input:** SDR captures IQ data $\rightarrow$ Jetson Nano processes it.
2.  **Analysis:** Calculates PSD, detects bursts, and demodulates signals (FM).
3.  **Storage:** Saves results to SQLite and writes raw IQ to disk.
4.  **Cleanup:** Monitors disk space; if low, deletes old `auto/` captures or archives old data.
5.  **Output:**
    *   Web UI for visualization and control.
    *   HTTP API for health checks and configuration.
    *   External integrations (OpenZMS, NATS).

### **Usage & Deployment**
*   **Installation:** `pip install .` (requires adding `~/.local/bin` to PATH if installed system-wide).
*   **Commands:**
    *   `rfobserver run`: Runs the full pipeline (with mock or real hardware).
    *   `rfobserver web`: Starts the local web UI.
    *   `rfobserver config`: Displays current configuration.
*   **Data Retrieval:** Captures can be downloaded via HTTP (supporting resumption via HTTP Range).
*   **Testing:** Includes unit tests (`hatch`) and integration tests against a mock NATS server.

### **Intended Use Case**
The system acts as an intelligent "gatekeeper" for radio astronomy. By continuously monitoring the spectrum and storing evidence of interference, it allows the observatory to dynamically grant access to specific frequency bands to other users or experiments only when the local environment is confirmed to be RFI-free.
