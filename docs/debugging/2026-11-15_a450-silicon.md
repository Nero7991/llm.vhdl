# a450 Task 8: tiled A on the Jungle Cat at 125 MHz (clock split off)

## 1. The question

2026-11-15. Card build `jccard_a450s0` from `81d1f48b` (`JC_A_TILED=1`, `JC_A_CLK_SPLIT` unset,
`--clk-mhz 125 --impl congestion`, `JC_LINK_REFCLK=gtg JC_LINK_RATE=10.3125`), both VU35P dies,
own-PC 27B images. Does the per-port tiled A (24 `mv_tile`s, built for 450 MHz) produce the same
values as the current A on silicon, and what does it do to A's cadence at today's 125 MHz?
Reference: `jccard_loop5` (A at 1.508 cycles per word, FAST_POP=false cadence limit).

## 2. The answer

Values are unchanged: the K1 token is 8678 with both dies' x-out dumps byte-identical to the
own-PC reference, and the 500-token context tests pass in both modes with ids identical to
loop5's. A's cost fell from 1.508 to 1.012 cycles per word on both dies (MEASURED), which takes
the seam cycles per token from 32.72M/32.84M to 28.65M/28.60M (-12.4%/-12.9%). At 125 MHz that is
0.229 s per die per token, a pair rate of 2.18 tok/s DERIVED (was 1.91).

## 3. Procedure

1. Build (`hw/jc/card/run_card.sh`, swap guard 30 GiB, `MemoryHigh=24G`, llama-server stopped).
   Gate: `^JCCARD_DONE`, `JCCARD_A450_SPLIT off`, `ECOA_DONE commons=1`, `JCCARD_GT_LOC
   GTYE4_CHANNEL_X0Y0`, `JCCARD_LINK_CDC_UNEXPECTED 0`.
2. Program both dies (`sqrl_bridge C<bmc> bit,bit skip`, from the BC-250).
3. Load own-PC weights and the side image per die (`coe_load.py load/verify`, `~/jca450/load_all.sh`
   on the BC-250, the loop5 recipe). Gate: `JCVERIFY_PASS 7170` (A), `6750` (B), `3` per side image.
4. Broker, forward, `jc_seam.py seam` per die: isolates load and seam from the compute path.
5. K1 anchor (`run_prompt` host path, `--max-new 1`, util counters cleared first): values.
6. `jc_seam.py util` right after K1: A's job cycles against the per-port beat count. `port_beats`
   equal to loop5's is the control that the layout and job list did not change.
7. `jc_ctxtest.sh pair|single ... 500` with `JC_LOOP=1`, GDN re-zero before every run.

## 5. Measured and REJECTED (do not retry)

- Reading the speedup from context-test wall time: pair output runs took 1054 s / 1058 s here
  against 1044 s / 1040 s on loop5. Those runs are host-transport bound (~2.1 s per GO through the
  ssh-forwarded broker, without the QUICKACK fix on the BC-250 repo copy), so a 0.03 s per-token
  card gain is invisible in them. Use the seam cycle counters.

## 6. Measurement traps hit

- `jc_bc_lane.sh stop` printed `JCLANE_DONE stop` while a broker started by hand from
  `/home/labuser/brkx` (the QUICKACK scratch copy) was still running: the lane script identifies
  its broker by `/proc/PID/cwd`, so a broker with another cwd is invisible to it. Programming and
  the load still succeeded, but the first context-test re-zero failed (`JCLOAD_ABORT connection
  lost`, the broker held the BMC). Stop such a broker by pid after checking its cwd. Attempts 1
  and 2 are kept under `ctxtest/attempt1`, `ctxtest/attempt2`.
- `jc_ctxtest.sh` checks for a live broker before its first re-zero: with none running it fails
  at once (attempt 2). Start one with `jc_bc_lane.sh start` first.
- The first build launch failed in under a second: `vivado` not on PATH (source settings64.sh).

## 7. Open, not yet answered

- The HBM port reset path (`hbm_rst` clearing `owed`) was not exercised: no lock loss occurred.
- c/word 1.012 is close to the 1.0 floor; the remaining 1.2% is not attributed.

## 8. Addendum 2026-11-15: gate 2, A at 450 MHz (clock split on)

### Question

Card build `jccard_a450s1c` from `1d662c24` (`JC_A_TILED=1 JC_A_CLK_SPLIT=1`, `--impl explore`, A's
floorplan and the aclk_a IP floorplan applied, uctr not built, descriptor fetch on clk_core behind
`d_cdc`). Same values as the current card with A on its own 450 MHz clock, and what is the token
cost? Two earlier split-on builds failed: `jccard_a450s1` (generator reset-topology refusal, fixed in
`1aee1631`/`1d040e50`) and `jccard_a450s1b` (A never floorplanned, aclk_a WNS -1.262; root cause in
`2026-11-15_a450-card-split-timing.md`).

### Answer

Values unchanged: K1 id 8678 with both x-out dumps byte-identical, and the 500-token context tests
pass in both modes with ids identical to loop5's. Seam cycles per token fell to 22.91M (die A) and
22.63M (die B) from 28.65M/28.60M with the split off and 32.72M/32.84M on loop5. Pair rate 2.74
tok/s DERIVED at the 125 MHz core clock (1 / (0.1833 + 0.1811) s).
