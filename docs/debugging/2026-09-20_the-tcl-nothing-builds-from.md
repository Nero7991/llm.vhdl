## The answer, up front

The premise is correct and the conclusion does not follow from it. MEASURED:

  records the environment of whoever last regenerated it, which at `46ae46b`

### The three structural facts that decide this

1. **Every committed intermediate is the next generator's input.** This is why
   `build_fk33_firstlight.tcl`, `build_fk33_i2cprobe.tcl` and
   `fk33_i2cprobe.xdc` are not optional, and it is invisible if you only ask
   "does a build script source this file".
2. **`build_fk33_firstlight.tcl`'s generator reads a repo we do not control and
   do not pin.** MEASURED: `gen_firstlight.py:19` is
   `SRC = os.path.expanduser("~/GitHub/SQRL_FK33/projects/fk33_example.tcl")`;
   that checkout is at `origin https://github.com/d953i/SQRL_FK33.git`, HEAD
   `4242680 "Update fk33_example.tcl"`, and nothing in this repo records which
   upstream commit the committed file was derived from. **It reproduced
   byte-exactly today only because that clone happens to sit at that path on
   this machine at that revision.** This file is the *most* load-bearing
   committed artefact in the set and the one nobody has been arguing about.
3. **The tcl is COPIED to `BUILD_ROOT`; the XDC is NOT.** That asymmetry matters
   for the leaf: a re-implementation driven from an existing `BUILD_ROOT` (the
   shape of `hw/fk33/results/card_swg_2026-09-20/reimpl.tcl`) sources the copied
   tcl but still reads `$tgRoot/hw/fk33/fk33_pcieep.xdc` from the repo. So the
   XDC's committed bytes *can* reach a tool; the tcl's cannot.

### The two host-side citations are comments and strings, not reads

MEASURED, `git grep` for `open(`/`read_text`/`source`/`cat` against these paths
outside `hw/fk33/results/`: the only hits are `pcieep_build.sh:249` and `:251`.
`host/fk33_run_token.py:86` is a comment. `host/fk33_run_job.py:942` is **inside

## What committing it BUYS, each claim assessed

**1. "It makes the build's configuration reviewable."** *Partly real, and
currently inverted.* There is no pull-request flow here -- a single branch with
direct commits -- and the configuration a reviewer wants is now sixteen lines of
GENSTAMP at the top of the file. Against that: MEASURED, the last regeneration
was `+133 -6`, of which **117 lines were drift from three earlier commits**
(`3219cb0` plus two BUILDREPORT changes). A reviewer reading that diff would
have attributed three other tracks' work to GENGATE's commit. **A 2,582-line
generated artefact in a diff obscures the configuration rather than exposing
it; the 16-line stamp exposes it.**

**2. "`git log` records what changed in the flow."** *False as stated, and
measurably so.* The output's history records *when somebody happened to
regenerate*, batched and lagging. The 117-line landing is the proof: three
distinct flow changes, made hours to days apart, arriving in one commit. The
accurate history of the flow is `git log hw/fk33/gen_pcieep.py` -- 42 commits,
each at the moment of the change.

**3. "Someone can read the flow without running a generator."** **REAL, and the
strongest of the four.** MEASURED: **59** line-number citations point into
`build_fk33_pcieep.tcl` and **22** into `build_fk33_hbmbw.tcl` from tracked
non-results files. `docs/2026-08-27_hbm-residency-map.md` cites
`build_fk33_hbmbw.tcl:483-738` and `:443-472` as *the evidence* for the 30-port
HBM address map; `docs/2026-08-27_weight-path-audit.md` builds on the same
lines. People do read these files as the design's reference, and 2,582 lines of
concrete Tcl are materially easier to read than the ~6,400-line Python that
emits them in fragments.

The same measurement is the cost, and it is why the recommendation below is
"keep it" and not "keep it and relax": **a line-number citation into a
generated file is stale by construction.** Independently verified at HEAD:

| citation | cites | actually at `08cc17d^` | actually at HEAD |
|---|---|---|---|
| `host/fk33_run_token.py:86`, `host/fk33_run_job.py:942` | `build_fk33_pcieep.tcl:781-782` for `DRAM_0_STAT_TEMP` | **902** | **942** |
| `tcl/axi_select.tcl:45` | `build_fk33_pcieep.tcl:251` for `jtag_hbm` `M_AXI_DATA_WIDTH 64` | **372** | **412** |

**4. "It is the artefact a bisect would need."** *No -- see the next section.*

## The bisect argument, measured rather than argued

Three commits sampled across the generator's history. For each: extract the
tracked tree at that commit with `git archive`, run `gen_i2cprobe.py` then
`gen_pcieep.py` in it, substitute the scratch root for the canonical one, and
diff against `git show <commit>:hw/fk33/build_fk33_pcieep.tcl`.

```
commit    date        env=DEFAULT          env=HEAD TRIPLE      env=FK33_CARD=1
ed1ffe2   2026-08-29  difflines=0          difflines=0          --
a182f9a   2026-09-08  difflines=0          difflines=420        --
46ae46b   2026-09-18  difflines=445        difflines=16         difflines=0
```

**3 of 3 reproduce byte-exactly, under three DIFFERENT environments.** So:

- **The generator at an old commit runs, and it is faithful.** The archive
  argument for committing the output is weaker than it looks: the output is
  derivable.
- **The environment was the whole difficulty, and only the environment.** At
  `a182f9a` the HEAD triple is wrong by 420 lines; at `46ae46b` both the
  defaults and the triple are wrong and the answer is `FK33_CARD=1` alone. I
  recovered each by reading the diff -- the `46ae46b` residual of 16 lines is
  literally `CLKOUT3_REQUESTED_OUT_FREQ {200.000}` against `{75.000}` plus the
  14-line lever-C block. **That is exactly the recovery GENSTAMP measured as
  costing a track real effort, and it is exactly what the stamp removes.**
- **THE STAMPS CHANGE THE ANSWER, FROM TODAY FORWARD ONLY.** Any commit at or
  after `08cc17d` carries the environment in the artefact's own header, so its
  flow is reconstructible from the generator. Commits *before* the stamps are
  not, and the committed output is their only record -- **but git keeps those
  bytes forever regardless of what is decided now.** Removing the file today
  removes nothing from history.
- **AND THE FILE IS NOT AN ARCHIVE OF ANY BUILD.** `pcieep_build.sh` regenerates
  before every build, so what built is the *generator plus the build's*
  environment. At `46ae46b` the committed file records `FK33_CARD=1` alone --
  the environment of the last person to regenerate, which need not be any
  build's. **The committed artefact answers "what did someone last generate",
  not "what was built", and those are different questions.** The thing that
  answers the second is `PROVENANCE.txt` (`pcieep_build.sh:160-179`, which
  records `git_head`, `git_dirty` and `env | grep '^FK33_'`).

**PROVENANCE.txt HAS NEVER BEEN PRODUCED.** MEASURED: `find hw/fk33/results
/mnt/storage/fk33_builds -name PROVENANCE.txt` returns **nothing**. The harvest
landed today and no build has completed through it. So the option "stop
committing it, the report directory records the environment" rests on a
mechanism that is designed, reviewed and **zero times observed**. That alone
disqualifies it as today's answer.

## A `--check` is not blocked. It needs two prefixes, not one

The standing reason for `gen_pcieep.py` having no `--check` (WORKLOG, open item
(a)) is that it writes absolute `add_files` paths for 104 sources.

MEASURED at HEAD, in an isolated `git archive` tree:

```
$ cd $SCR/tree/hw/fk33 && FK33_CARD=1 FK33_CB_STYLE=distributed \
      FK33_ENG_CORE_MHZ=75 python3 gen_pcieep.py
wrote .../tree/hw/fk33/build_fk33_pcieep.tcl
wrote .../tree/hw/fk33/fk33_pcieep.xdc  (48 lane constraints superseded, ...)
$ sed "s#$SCR/tree#/home/orencollaco/GitHub/llama.vhdl#g" <regen> | diff <committed> -
   tcl difflines=0
   xdc difflines=0
```

So the committed pair is **currently in sync**, and a path-canonicalising check
would report OK today. The idiom already exists in this repo:
`gen_fk33_card.py`'s `_canon_hexpaths` rewrites the repo prefix to `@REPO@`,
compares the canonical text, and **reports** the observed prefix instead of
checking it, with the comment that a foreign prefix "is legal (a worktree
comparing a committed file) but it is also exactly what a post-rename stale file
looks like, so it must be visible rather than absorbed." That is the right
shape here too.

**The trap for whoever writes it: there are TWO prefixes.** MEASURED on the
regenerated file:

```
/home/orencollaco/GitHub/llama.vhdl        x122   add_files, and the tgRoot candidate list
/home/orencollaco/GitHub/SQRL_FK33         x2     :183 set scriptPath, :208 set sourceRoot
```

The second is inherited down the chain from `build_fk33_firstlight.tcl` and
points **outside this repository**. A canonicaliser that folds only the repo
root leaves those two lines machine-specific, and a check built on it would be
green on this box and red everywhere else -- the muted-row failure GENGATE's
attribution control was written to avoid.

## MEASURED AND REJECTED -- do not retry

- **"Delete `build_fk33_pcieep.tcl`; the generator plus the stamp is enough."**
  REJECTED on the 59 citations and on claim 3 above. The file is the reference
  people read; the generator is not a substitute for it. It also carries the
  stamp itself, so deleting it deletes today's only durable record of the
  environment until a build produces a `PROVENANCE.txt`, of which there are
  **zero**.
- **"Delete it and write it into `FK33_REPORT_DIR` instead."** REJECTED, for now.
  The report directory is only written by `pcieep_build.sh`, so a `--bd-only`
  run or a hand-run generator produces nothing, and the mechanism has never once
  run to completion. Revisit when several `PROVENANCE.txt` files exist.
- **"The generator at an old commit does not run, so the committed output is the
  only archive."** REJECTED, MEASURED: it runs at 3 of 3 sampled commits and
  reproduces exactly. My own first attempt said otherwise -- see the traps.
- **"`FK33_CARD=1 FK33_CB_STYLE=distributed FK33_ENG_CORE_MHZ=75` is *the*
  environment."** REJECTED as a general statement. It is the environment of the
  HEAD file only. At `a182f9a` it is wrong by 420 lines and at `46ae46b` by 16.
  **Read the stamp in the file in front of you; never carry a triple forward

- **"A `--check` is impossible because of the absolute paths."** REJECTED: one
