# attn_recip: three mutation survivors, one real gap and two genuine equivalences

**Date:** 2026-08-27
**Build:** `llama.vhdl` branch `fpga`. New files, never committed with a defect
present. GHDL 1.0.0 mcode backend, `ghdl -r` direct, no `ghdl -e`.
**Unit:** `rtl/attn_recip.vhd`, subsystem C step 8a, the softmax reciprocal, at
`S_W = 26`, `R_W = 16`, `R_Q = 15`, `NW = 44`, `DW = 28`.

Companion to `2026-08-27_attn-softmax-offset-resize.md` from the same session.
That one records an RTL defect; this one records three things that are easier
to get wrong than the RTL was: a guard no vector reached, a mutation that
mutated nothing, and a testbench name that silently hid a generic.

## The question

`rtl/attn_recip.vhd` passed `sim/tb_attn_recip.vhd` bit-exactly on both `p` and
`r` at the first run, in every configuration, over 24 layers x 12 heads and
again over 60 x 24. The question was therefore not "is it right" but the one
that matters: **which of its properties did that pass actually test?**

The first mutation run answered it: **11 of 15 killed, four survivors.**

## The answer

Of the four, **one was a real coverage gap in the testbench and three were
equivalences -- but only two of those three were equivalences of the DUT.** The
third was an equivalence of the MUTATION: it changed nothing at all.

| survivor | verdict |
|---|---|
| N6, quotient truncated instead of saturated | **equivalent.** `r <= 2^R_Q = 32768 < 2^R_W`, so the saturate is unreachable. Proven, not assumed, by the reference's oracle 2, which checks `2^14 <= r <= 2^15` as an exact inequality on every head. |
| N9, quotient captured on `busy = '0' and start = '0'` instead of on `done` | **equivalent.** `divider_rs` assigns `r_busy <= '0'` and `r_done <= '1'` on the SAME edge, and `S_WAIT`'s first cycle has `busy = '1'` because `start` was high the cycle before. The two conditions are true in exactly the same cycle. Established by reading `rtl/divider_rs.vhd`, not by the pass. |
| N7, the `s = 0` trap removed | **A REAL GAP.** Fixed by adding a zero probe to the testbench; now killed in all three configurations. |
| N13, `done_r <= '1'` asserted in `S_SAT` | **the MUTATION was a no-op.** Rewritten; the new form is killed in two of three. |

Final: **13 of 15 killed, 2 survivors, both equivalent.**

## The procedure that produced it

1. **Build the C reference first, with oracles that share none of the integer
   path.** The one that carries the weight here never divides at all:
   `r = floor(N/s)` if and only if `r*s <= N < (r+1)*s`, and both products are
   exact in 64 bits (`r <= 2^15`, `s < 2^26`, so `r*s < 2^41`). Checking a
   division by dividing again in double would be a restatement, not a check.
2. **Mutation-test the C reference before trusting the RTL against it.** 7
   mutations, 6 killed; the survivor (`R8`, the `R_W` clamp removed) is the same
   unreachable saturate that `N6` later hit from the RTL side, which is a
   consistency check on both.
3. **Mutation-test the RTL, then READ every survivor.** This is the step that
   found the gap. A survivor is a question, and three different answers came
   back to what looked like one question.
4. **For the gap, add the probe rather than the vector.** `s = 0` cannot be
   generated by the reference -- `attn_softmax`'s grid snap floors the
   denominator at 3849, so a golden containing `s = 0` would be a golden for a
   contract violation. The testbench drives it as an explicit final phase
   instead, in the style of `tb_attn_score_q12`'s OVERRUN PHASE.

## Measured and REJECTED -- do not retry

- **"A survivor means the property is untested."** Not necessarily, and
  conflating the three cases is the expensive mistake. N6 and N9 are properties
  that cannot be tested because they cannot differ; N7 was a property that was
  genuinely untested; N13 was a mutation that did not change the circuit. Only
  reading separates them, and only the second one is worth fixing.
- **Asserting `done_r <= '1'` early as a "done is raised too soon" mutation.**
  It is a NO-OP. The process ends with
  `if state /= S_DONE then done_r <= '0'; end if;`, which is a LATER assignment
  to the same signal and wins, so an early assertion anywhere in the case
  statement is erased on the same edge. This is the same VHDL asymmetry the
  RULE 1 comment in every one of these units describes from the other direction
  -- an explicit clear inside the ack branch also wins, and there it destroys
  the pulse. To mutate "done too early" you must move the STATE, not the
  signal: `S_OUT` leaving for `S_DONE` without waiting for `r_ready` is killed
  in two of three configurations.
- **Relying on the golden to reach a guard.** The reference cannot emit
  `s = 0`: the softmax's grid snap makes the largest score's own weight at least
  `round(exp(-255/4096) * 4096) = 3849`, so a vector containing `s = 0` would be
  a golden for something the producer cannot produce. **A guard no vector
  reaches is not a guard, it is a comment**, and mutation N7 said so. The fix is
  a deliberate contract-violation phase in the testbench, not a widened
  generator.

## Measurement traps hit

- **A testbench variable named `nhead` HIDES the generic `NHEAD`.** VHDL is
  case-insensitive, so `variable nhead : integer;` inside the stimulus process
  shadows the generic for the whole process, and the vector-file shape assertion
  then compared the file's head count against an **uninitialised integer**. The
  run died at `tb_attn_recip: vector file shape mismatch`, which reads exactly
  like a malformed golden and sends you to the generator. GHDL says so plainly
  -- `warning: declaration of "nhead" hides generic "nhead" [-Whide]` -- one
  line above the failure, and it was scrolled past on the first read. **Read the
  warnings above a shape-mismatch assertion before touching the generator.**
- **`wait until rising_edge(clk)` resumes in the SAME delta as the edge**, so a
  `_taken` pulse the DUT assigns on that edge still reads as `'0'`. The
  testbench waits `1 ns` past the edge at the `s_taken` check. Carried over
  from `tb_attn_kv_quant`; it has now been the right call three times.
- **The DEGENERATE configuration is not strictly weaker.** N14 -- the
  `gdn_head_emit` anti-pattern -- is killed ONLY by the configuration with both
  acks prompt, and survives both lagged ones; N12, N13 and N15 are killed only
  by the lagged ones. Four of the five interface mutations need a specific
  configuration, and no single one catches them all.
- **The `s = 0` probe makes the DUT's own `STRICT_PRODUCER` assertion fire, by
  design.** The run prints
  `attn_recip: s = 0 offered ...` at `severity error` and still reports PASS,
  because GHDL's default stop level is `failure` and the testbench counts only
  its own `nerr`. That is intended -- the assertion message is the expected
  observable of the probe -- but a reader scanning for "error" in the log will
  see it. It is called out in the testbench header for that reason.

## Open, not yet answered

- **No Vivado.** `attn_recip` declares **152 flip-flops** of its own plus
  **152** in its `divider_rs` instance at `NW = 44, DW = 28`, for **304** total,
  counted from the signal declarations. It contains **no datapath multiply**
  (the only `*` in the file is the compile-time constant `2**R_W`), so it should
  infer **0 DSP**, which is what the C DSP skeleton books it at. `divider_rs`
  was MEASURED at 0 DSP on 2026-08-25. Both figures are counts and an
  inference, not a measurement, and the Fmax is unknown.
- **The divide is 44 cycles and `s_ready` is low for all of it.** That is a
  long stall by this design's standards. It is affordable because it happens 12
  times per layer and not 12 times per position -- 192 divides per token per
  card, under 9,000 cycles of a 1.3-million-cycle subsystem -- but nothing
  enforces that the producer can actually wait, and `attn_softmax` has no
  overrun flag on `s_out` the way `attn_score_q12` has `ovr` on its score.
- **`err` and `ovr` have no policy**, the same state every other flag in this
  subsystem is in.
- **The 12-head batch is driven one head at a time.** The C spec says the
  divider is shared across the 12 query heads of a layer, which this unit does,
  but it does not overlap the msb scan of head h+1 with the divide of head h.
  At 192 divides per token that is not worth doing, and it is not done; stated
  so nobody assumes it is.
