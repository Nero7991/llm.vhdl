# How a D step finds its A descriptor, and why the answer had to be checked

**Date:** 2026-09-03
**Files:** `rtl/a_desc_ptr.vhd`, `rtl/matvec_int4_desc_pkg.vhd`,
`rtl/matvec_int4_desc_axi.vhd`, `sim/tb_a_desc_ptr.vhd`, `sim/tb_a_geom.vhd`,
`tools/gen_mv4i_desc.py`, `tools/gen_layer_program.py`,
`docs/2026-08-28_matvec-descriptor-format.md`

## The question, verbatim

From the standing blocker list: *"(1) A's descriptor base-array fetch
integration (DESC_PTR sourcing is unresolved design decision)"* and *"(4)
descriptor index limitation (job_ordinal 8-bit cannot address 311 jobs)"*.

And from `tools/gen_layer_program.py` itself, written 2026-08-30:

> WHAT NOTHING SUPPLIES: the pointer from a D step to its A descriptor. [...]
> which mechanism delivers them to the card is an open integration decision,
> not a derivation. Stated, not invented.

## The answer

**Blockers 1 and 4 were one decision, not two.** `DESC_PTR` and `a_job_index`
are two faces of the same missing field, which is why both were exported as
top-level inputs of the composed top rather than wired: the design deliberately
kept the gap visible instead of guessing.

The decision, taken by Oren on 2026-09-03: **the card counts.**
`rtl/a_desc_ptr.vhd` holds the number of A jobs dispatched so far in the
current token and emits

```
desc_ptr  = BASE + n * STRIDE
job_index = n
```

No descriptor format change was strictly required for that. One was made
anyway, and that is the substance of this file.

## Why an arithmetic pointer needed a new descriptor field

Arithmetic addressing does not remove the problem, it MOVES it: it imposes an
**ordering contract** on the host, which must lay the descriptors out in the
schedule's A-job order.

An unchecked ordering contract produces a **wrong token rather than an error**.
A well-formed descriptor for the wrong step passes every single check in
`matvec_int4_desc_axi`'s `S_CHECK` -- magic, version, geometry, opcode, four
pad fields, shape, all of it -- because **nothing else in a descriptor says
which step it belongs to**. The format document already records the analogous
hole for sub-region CONTENTS in section 5.1: "a base that is well-formed but
points at the WRONG sub-region [...] produces a wrong answer rather than an
error."

So descriptor **version 2** stamps the descriptor's own A-job index into
extension word 3's low half, `matvec_int4_desc_axi` compares it against the
`job_index` port, and a mismatch is refused `EC_DESC` / `ED_JOB_INDEX` before
the array is started. Version 1 remains accepted, so this is an extension and
not a break.

`job_ordinal` was never a candidate. It is `unsigned(7 downto 0)`
(`seq_desc_fetch.vhd:214`), so it cannot address 311 jobs, and it already means
the per-kind layer index -- defect ORD-1,
`docs/debugging/2026-08-29_ordinal-two-meanings.md`. Reusing it would have
recreated a defect that took a day to untangle.

## The procedure

Three separable pieces, each verified on its own before any of them met.

1. **The format**, in `matvec_int4_desc_pkg.vhd`: `MV4I_DESC_VER_IDX = 2` and a
   new `ED_JOB_INDEX = 14` sub-case. The version check in
   `matvec_int4_desc_axi` widens to accept 1 or 2; extension word 3's pad check
   splits into a high half checked in both versions and a low half that is pad
   in v1 and the index in v2.
2. **The pointer source**, `rtl/a_desc_ptr.vhd`.
3. **The producers**: `gen_mv4i_desc.py` gains a `job_index` argument that
   selects the version and stamps the field, plus the matching verify arms;
   `gen_layer_program.py` stamps it for every A step.

## Two things the EXISTING checks caught, which is the best evidence here

Neither was found by inspection. Both were found by a check that already
existed doing exactly what it was written to do.

**1. `sim/tb_matvec_fk33_desc.vhd` case 2 was "ext version = 2 must be
refused".** Legalising version 2 turned that row red across all three of its
gate configurations (`tb_matvec_fk33_desc`, `_dual`, `_xexp` share one body):

```
CASE 2 ext version = 2 -> NOT DETECTED: no err after 219 polls (done='1')
CASE 2 ext version = 2 -> reported DONE as well as err
CASE 2 ext version = 2 -> emitted 100 result elements despite being rejected
```

Retargeted to version **3**, which is still unknown. Leaving it at 2 would have
left a mutation row that mutates to something legal, i.e. a check that can
never fail -- the silent-decoration outcome this project keeps finding. The row
is stronger for having been retargeted than it would have been had the change
never touched it.

**2. `CHECK_JOB_INDEX` defaulting TRUE would have broken the card.** Found by
reading `hw/fk33/rtl/fk33_engine.vhd:1266` rather than by a test, because no
test covers the card's host-driven flow. On the card the HOST writes
`DESC_PTR` over AXI-Lite once per job and there is no counter, so `job_index`
sits at its all-zero default. With the check on, every v2 descriptor stamped
with a nonzero index -- which is every A job but the first, now that
`gen_layer_program.py` stamps them -- would have been refused, and the flow
that produced *311 of 311 jobs, 1,675,264 result rows element-exact* would have
stopped working.

Default flipped to **false**. Opting in is the safe direction: forgetting to
opt in loses a check, forgetting to opt out breaks a working card.
`sim/tb_a_geom.vhd` opts in explicitly, which is why the teeth above still
bite.

## Measurement traps hit

- **`err_code 15` is `EC_SHAPE`, not acceptance.** The mutant descriptors are
  still refused, just for a *different* reason further down `S_CHECK`. The
  first draft of these bench messages said the descriptor "was accepted",
  which overstates: the correct claim is "was not refused with
  `ED_JOB_INDEX`". Reworded before commit. A bench message that overstates
  what it observed is a bench message that will be quoted.
- **A parallel A-job counter in `gen_layer_program.py` would have drifted.**
  `addr` advances only on the SUCCESS path, so a refused step consumes no
  slot, while a counter incremented per A step would keep counting. The stamp
  is therefore DERIVED from the address slot, `(addr - desc_base) // a_slot`,
  which makes the two incapable of disagreeing. If the tool ever emits a
  sparse table, the card's dispatch count then disagrees with the stamp and
  the v2 check refuses it loudly, which is the outcome we want.
- **`BASE + n*STRIDE` cannot address a ragged table.** Slot size is uniform for
  a given build because descriptor length is `DESC_BASE0 + npw + nps +
  DESC_EXT_WORDS` words and all of those are build constants. The tool now
  raises rather than assuming it.
- **`2**ADDR_W` overflows a VHDL integer at ADDR_W >= 32.** The first draft of
  `a_desc_ptr`'s address-space refusal hardcoded `2**30`, which silently did
  not depend on `ADDR_W` at all. Expressed through `clog2` instead.

## A measurement trap worth its own heading: I edited a bench mid-run

The first subset run produced this, and it is internally inconsistent:

```
tb_matvec_fk33_desc       PASS 0  FAIL 3
tb_matvec_fk33_desc_dual  PASS 0  FAIL 1
tb_matvec_fk33_desc_xexp  PASS 1  FAIL 0
```

All three rows share ONE body, `sim/tb_matvec_fk33_desc.vhd`, so they cannot
disagree about case 2. They disagreed because **I edited that file while the
run was in flight**, and `regress.sh` compiles from the repo per row: the rows
that started before the edit saw the old case, the rows after saw the new one.
The first line's `FAIL 3` is the substring invocation (`--only` is a SUBSTRING,
so it matched all three at once); the later per-row lines are separate
invocations that straddled the edit.

**A green row from a run that overlapped an edit proves nothing about either
version of the file.** Only the run started after the last edit counts. Cheap
to get wrong because the output looks like a normal mixed result rather than
like a corrupted measurement.

## And a second one: a stale scratch directory read as a fresh result

`ls` on the gate's scratch directory returned a complete-looking listing of
~230 row directories covering every bench in the project. It was **a directory
from a previous session, dated Sep 2 19:39**, and the gate that was supposed to
have written it had not started yet -- it was still queued behind another run.

The tell was that neither `sim_tb_gdn_job_seq` nor `sim_tb_a_desc_ptr` appeared
in it, which is what prompted the check. Had both new rows been named something
that already existed, nothing would have looked wrong.

**A scratch path reused across sessions produces output that is
indistinguishable from a fresh run until you look at the timestamps.** Name
scratch directories per run, and check `ls -la` rather than `ls` when a result
appears suspiciously complete.

## Measured and REJECTED -- do not retry

- **Reusing `job_ordinal`.** 8 bits against 311 jobs, and it already carries
  the per-kind layer index. Not a width problem that widening fixes; it is two
  meanings in one field, which is defect ORD-1 exactly.
- **An unchecked arithmetic pointer.** Rejected on the argument above rather
  than by measurement: it passes every existing check by construction, so
  there is no experiment that would have caught it. That is the reason it
  needed a new field rather than a comment.
- **A dense side table in HBM** (`a_desc_ptr[step]`, one fetched pointer per A
  job) and **a new 32-bit field in D's step header** were both offered and both
  declined. Recorded because they are the fallbacks if the ordering contract
  ever becomes inconvenient: the side table costs a region, a module, a bench
  and one HBM read per A job, and buys freedom from any layout order; the
  header field costs the D spec, `gen_layer_program.py`, `seq_desc_fetch.vhd`
  and the URAM model in `tb_llama_top.vhd:705` moving together.

## Open, not yet answered

- **`rtl/llama_top.vhd` does not instantiate `matvec_int4_desc_axi` at all.** It
  instantiates the raw `matvec_int4` (`llama_top.vhd:3335`) and synthesises A's
  bases arithmetically (`:3535-3539`). Swapping it needs an AXI-Lite master to
  program `DESC_PTR`, a descriptor read port, and descriptor images present in
  the simulation path. That is integration work and it has not been started.
  **The mechanism in this file is decided, implemented and verified as a unit,
  and is not yet connected to anything.**
- **Nothing pulses `a_dispatch` or `tok_start`.** Both are inputs waiting on
  the same integration.
- **`A_DESC_BASE` and `A_DESC_STRIDE` are not yet in the region map.** The
  stride is a generic with a checked default; the base is a runtime input.
- **The 311 figure is quoted from `gen_layer_program.py`'s own output at the 9B
  shape and has not been re-derived here.**
